# دليلُ التسليم — للمهندس البديل

> إن غاب من يشغّل النظامَ، هذا ما يحتاجه من يخلفه في يومه الأول. الأسرارُ تُذكَر بأسمائها لا بقيمها — القيمُ عند صاحب المشروع وفي مخزن GitHub.

## ١ · ما الذي يعمل الآن (لا تلمسه في أوّل يوم)
- التطبيق: `https://mhmdsfwt371.github.io/Project-survey/` — يُنشَر من فرع `main` تلقائيًّا.
- القاعدة: مشروع Firebase `project-survey-60600` (Firestore + Authentication) — خطة Spark.
- السيورُ المجدولة (GitHub Actions): النسخُ الليلي ٥:٣٠ صباحًا مكة · النبضُ ٦:٣٠ · التقريرُ كلَّ ثلاثة أيام · لقطةُ الوزارة كلَّ ٦ ساعات وPDF السبت · التغذيةُ والإنشاءُ عند الحاجة.
- كلُّ ذلك يعمل بلا يد — راقب فقط: **صحة النظام** في التطبيق (سلامةُ البيانات · الاستهلاك · النبضُ والتقرير).

## ٢ · كيف تشغّل وتنشر
1. استنسخ المستودع وثبّت البيئة (الأمرُ الوحيد المسموح — `AGENTS.md` §٢):
   ```bash
   git clone https://github.com/mhmdsfwt371/Project-survey.git && cd Project-survey
   npm i --no-save --no-audit --no-fund jsdom@^24 docx@^9 jszip@^3
   ```
2. اقرأ `AGENTS.md` كاملًا — هو دستورُ العمل: دورةُ الإصدار، والفروع، وقواعدُ الشيفرة التي تُسقطها الجرود.
3. أيُّ تغيير = نسخةٌ جديدة (`AGENTS.md` §٤) + جردٌ دائم + `node scripts/check-version.mjs` كاملًا ثم `git push origin HEAD:staging`.
4. البوابةُ في السحابة تفحص وترقّي إلى `main` وحدَها. الفشلُ يُكتَب تعليقًا على الالتزام (لا تشغيلٌ أحمر) — اقرأه وأصلح.
5. لا تدفع إلى `main` مباشرةً، ولا تعِد كتابةَ التاريخ، ولا تثبّت حزمةً خارج القائمة.

## ٣ · كيف تستعيد نسخةً احتياطية
- المصدر: Google Drive ← مجلد «نسخ احتياطية — متابعة المشروع ١٤٤٨هـ» ← مجلد اليوم ← `backup-full.enc` (+ `photos.enc`).
- الفكّ (يحتاج `BACKUP_KEY` من صاحب المشروع):
  ```bash
  openssl enc -d -aes-256-cbc -pbkdf2 -iter 250000 -in backup-full.enc -out backup-full.json -pass env:BACKUP_KEY
  node scripts/backup-verify.mjs backup-full.json _meta.json     # تطابقُ الأعداد
  ```
- الملفُّ الناتج JSON بكلِّ المجموعات (`recs` الزيارات · `inss` التركيبات · `tasks` · `users` …). الإعادةُ إلى القاعدة قرارُ صاحب المشروع وتُنفَّذ بحساب الخدمة عبر سكربتٍ يُكتَب لها وقتَها — لا تُعاد وثائقُ `users` إلا بعد مراجعة.
- بروفةُ الاستعادة تعمل كلَّ ليلةٍ آليًّا؛ إن سقطت وصل بريدٌ (إن ضُبط SMTP) وظهرت البطاقةُ حمراءَ في صحة النظام.

## ٤ · أين كلُّ سرّ (الأسماءُ فقط)
| السرّ | أين | ما يفعل | من يملك قيمته |
|---|---|---|---|
| `FIREBASE_SERVICE_ACCOUNT` | GitHub Secrets | حسابُ الخدمة — قراءةُ القاعدة وكتابتُها من السيور | Google Cloud ← IAM ← Service Accounts (يُولَّد ولا يُستعاد) |
| `BACKUP_KEY` | GitHub Secrets + موضعان خارجه | تشفيرُ النسخ وفكُّها — بدونه النسخُ ملفاتٌ لا تُفتَح | صاحبُ المشروع |
| `GDRIVE_SA` · `GDRIVE_FOLDER` | GitHub Secrets | رفعُ النسخ إلى الدرايف | صاحبُ المشروع (المجلدُ مشارَكٌ مع بريد حساب الخدمة) |
| `MINISTRY_SECRET` | GitHub Secrets | رمزُ اليوم للصفحة المشتركة | صاحبُ المشروع |
| `SMTP_HOST` · `SMTP_PORT` · `SMTP_USER` · `SMTP_PASS` · `MAIL_FROM` · `MAIL_TO` | GitHub Secrets | البريدُ من السيور | صاحبُ المشروع |
| `MYAFAQY_TOKEN` (أو `MYAFAQY_USER`/`MYAFAQY_PASS`) + المتغيّرات `MYAFAQY_*` | GitHub Secrets / Variables | جسرُ ماي أفاقي — خاملٌ حتى يُضبَط `MYAFAQY_BASE` | أفاقي |
| مفتاحُ تشغيل السيور (`ghcfg` في القاعدة) | يُلصَق في التطبيق كمدير | إطلاقُ سير الإنشاء من التطبيق | صاحبُ المشروع — توكن دقيقُ الصلاحيات، Actions فقط، بتاريخ انتهاء |
| كلماتُ مرور الحسابات | لا تُخزَّن | تُنشَأ مؤقتةً في ورقة الدخول ويغيّرها صاحبُها | — |

## ٥ · كيف تدوّر مفتاحًا
- **حسابُ الخدمة**: Google Cloud ← IAM ← Service Accounts ← `firebase-adminsdk` ← Keys ← Add key (JSON) ← الصق محتواه في `FIREBASE_SERVICE_ACCOUNT` و`GDRIVE_SA` ← شغّل سيرَ النسخ يدًا وتأكّد ← احذف المفتاحَ القديم من الصفحة نفسِها.
- **`BACKUP_KEY`**: لا يُدوَّر إلا مع الاحتفاظ بالقديم لفكِّ النسخ السابقة — سجّل تاريخَ التبديل في `docs/deadlines.json`.
- **مفتاحُ السيور**: GitHub ← Settings ← Developer settings ← Fine-grained tokens ← هذا المستودع فقط ← Actions: Read and write ← تاريخُ انتهاء ← الصقه في التطبيق (الإعدادات ← ثوابت النظام ← بطاقةُ التشغيل) ← أضف الانتهاءَ إلى `docs/deadlines.json`.
- **`MINISTRY_SECRET`**: غيّره في Secrets — الرمزُ اليوميُّ يتغيّر من اللقطة التالية (٦ ساعات).
